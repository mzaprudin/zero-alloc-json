# Сборка и разработка

[English](development.md) · [Русский](development.ru.md)

Python 3 нужен для проверки документации и CI-скриптов. Изменения C# и параметров сборки также требуют .NET 10 SDK. Все пакеты имеют фиксированные версии; packages.lock.json проверяются в locked restore.

## Документация и оформление README

Для Markdown в корне, `docs/`, `results/`, изображений README и скриптов оформления:

```sh
python scripts/verify-docs.py
python -m unittest discover -s scripts -p 'test_*.py' -v
```

Проверяются ссылки Markdown и HTML, пути к локальным изображениям, синтаксис и зависимости SVG, синтаксис Python, сгенерированные таблицы бенчмарков и сохранённые результаты. Архивные отчёты остаются побайтно неизменными. При изменении генератора пересоздайте таблицы из [опубликованного набора](../results/local/published-run.json) и проверьте результат. Публикация одной документации не требует сборки .NET, тестов, запуска примера или новых измерений.

## Код и параметры сборки

Для библиотеки, тестов, вспомогательного кода, примеров, бенчмарков, фикстур, зависимостей и параметров сборки:

```sh
dotnet restore ZeroAlloc.Json.sln --locked-mode
dotnet build ZeroAlloc.Json.sln -c Release --no-restore
dotnet test tests/ZeroAlloc.Json.Tests -c Release --no-build
dotnet run -c Release --no-build --project samples/ZeroAlloc.Json.Demo
dotnet run -c Release --no-build --project benchmarks/ZeroAlloc.Json.Benchmarks -- --filter '*' --job dry
python scripts/verify-docs.py
```

Для чистой проверки создайте новый git clone и выполните те же команды. Также запускайте соответствующие тесты скриптов. Для таких изменений CI запускает все тесты, пример и каждый benchmark-сценарий с `--job dry` на Linux и Windows. Dry проверяет работоспособность; для таблиц используются реальные длительные замеры.

## Объём и запуск CI

Автоматический CI запускается при push в `main` и в pull request. Рабочие ветки проверяются через pull request, без дублирования push/PR. Новый коммит отменяет устаревший прогон того же workflow и ветки/PR.

Один Ubuntu-job определяет объём полного diff push или PR и проверяет документацию и результаты. Матрица Linux/Windows запускается при изменении кода, конфигурации CI или неизвестных файлов. При переименовании учитываются оба пути. Ручной запуск, неполные данные события и недоступная история всегда выбирают полный CI.

При изменении workflow, классификатора или логики проверки документации локально проверяйте синтаксис workflow, Python-тесты, документацию и результаты, затем подтвердите один полный прогон на GitHub. Повторять неизменённые .NET-проверки локально только ради CI-правок не требуется. Правила маршрутизации находятся в [ci_changes.py](../scripts/ci_changes.py), локальных проверок — также в [AGENTS.md](../AGENTS.md).
